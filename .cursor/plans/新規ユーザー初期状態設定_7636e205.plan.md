# 新規ユーザー初期状態設定

- 対象は「DBに未登録の初回サインアップ時」のみ。トリガー `handle_new_user` とデフォルト挿入関数の変更で実現する。

## 1. 新規ユーザー用デフォルト値の変更（SQL）

トリガーとデフォルト挿入関数を、次の内容に合わせて更新する。

**参照・修正対象:**

- [docs/sql-snippet/fix-trigger-handle-new-user.sql](docs/sql-snippet/fix-trigger-handle-new-user.sql) … `handle_new_user` の実体
- [docs/sql-snippet/supabase-setup.sql](docs/sql-snippet/supabase-setup.sql) … `create_default_habits_for_user` の定義（ドキュメント・新規環境用）
- [docs/appendix/DATABASE_SCHEMA.md](docs/appendix/DATABASE_SCHEMA.md) … 上記と整合する説明

**実施内容:**

1. **handle_new_user**
  - `profiles` の初期 `points` を **10 → 50** に変更。
  - `rights_config` を新規ユーザー用に明示設定（`profiles` に `rights_config` が存在する前提）。値は権利Aのみ:
    - `{"A": {"points": 5, "name": "TVゲームをやる (2時間)"}}`
  - 既存の `create_default_habits_for_user(NEW.id)` に加え、**デフォルトToDo挿入**用の新しい関数を呼ぶ（下記）。
2. **create_default_habits_for_user の置き換え**
  - 挿入内容を仕様どおりの最小セットに変更:
    - **良習慣 1件:** `早起きする｜8時まで`（habit_type: good, 他は既存スキーマに合わせて適宜デフォルト）
    - **悪習慣 1件:** `無目的なYouTube視聴`（habit_type: bad）
  - 既存の多数行INSERTは削除し、上記2件のみINSERTする定義に書き換える。
  - この定義は **fix-trigger 用のSQL** と **supabase-setup.sql / DATABASE_SCHEMA.md** の両方で一致させる。
3. **create_default_todos_for_user の新規作成**
  - 引数: `user_id UUID`
  - 処理:
    - `todos` に1件INSERT: `task_name = 'テストタスク'`, `status = 'active'`, `due_date = '2026-12-31'`, `display_order = 0`（他はテーブルデフォルト）。
    - 上記で生成された `todos.id` を使い、`todo_subtasks` に1件INSERT: `subtask_name = 'サブタスク サンプル'`, `display_order = 0`。
  - `handle_new_user` 内で、`create_default_habits_for_user` と同様に **EXCEPTION で囲んで** 呼び出す（失敗してもプロファイル作成は成功させる）。

**SQLの配置方針:**

- 本番で既に `fix-trigger-handle-new-user.sql` を実行済みなら、**新規マイグレーション用の1ファイル**（例: `set-new-user-defaults.sql`）を用意し、以下をまとめて実行する形がよい:
  - `create_default_habits_for_user` の REPLACE（上記2件のみ）
  - `create_default_todos_for_user` の新規作成
  - `handle_new_user` の REPLACE（points 50, rights_config 設定, create_default_todos_for_user 呼び出し追加）
- `rights_config` は [docs/sql-snippet/supabase-add-rights-config.sql](docs/sql-snippet/supabase-add-rights-config.sql) で追加されている前提。未適用の環境では先にこちらを実行する必要があることをコメントで明記する。

## 3. 仕様メモとの対応

- **ゴルド 50G** … `handle_new_user` の `profiles.points = 50` で実現。
- **良習慣「早起きする｜8時まで」** … `create_default_habits_for_user` で1件INSERT。
- **悪習慣「無目的なYouTube視聴」** … 同上で1件INSERT。
- **本日の利用ゴルド「権利A｜TVゲームをやる (2時間) 1回あたり -5G」** … 新規ユーザーの `rights_config` を権利Aのみ（name: "TVゲームをやる (2時間)", points: 5）にすることで、日誌の「利用ゴルド」に権利Aだけが表示される。既存ユーザーは変更しない。
- **ToDo: アクティブ1件「テストタスク」期限 26/12/31、サブタスク「サブタスク サンプル」** … `create_default_todos_for_user` で挿入。
- **既存アカウント** … トリガー・関数の変更は「新規INSERT時」のみに効くため、既存3アカウントのデータはそのまま。

## 4. 確認事項（実装前に確認推奨）

- **期限 26/12/31** … 2026年12月31日（`due_date = '2026-12-31'`）でよいか。
- **習慣のポイント・EXP** … 良習慣・悪習慣それぞれ、既存の `habits` スキーマ（points, exp_body, exp_mind, exp_spirit, input_type, exclude_from_complete 等）に合わせてデフォルト値を入れる。仕様に明示がなければ 1/0/0/0 や checkbox など既存の「1件あたり」のデフォルトでよいか。
- **rights_config の unit** … API・UIが `unit` を参照している場合は、新規ユーザー用の権利Aに `"unit": "1回あたり"` などを含めるかどうか。含めない場合は既存のフォールバック表示に従う。
