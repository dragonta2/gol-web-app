# 表示名がデフォルトになる問題の修正プラン

## 現在の処理フロー

### A. ニックネーム保存の流れ（設定画面 → DB）

```
設定画面（ブラウザ）
  ├─ 入力: 表示名テキスト + 「GOL世界の表示名として利用する」チェック
  └─ 保存ボタン押下
       ↓
  fetch PATCH /api/user/profile
  body: { username, use_username_as_display_name }
       ↓
  app/api/user/profile/route.ts（PATCH）
  ├─ 1回目 UPDATE: profiles.username のみ更新
  └─ 2回目 UPDATE: profiles.use_username_as_display_name を更新
     （失敗しても console.warn でスキップ）
       ↓
  レスポンス 200 { username, use_username_as_display_name }
       ↓
  クライアント: toast「保存しました」
  ※ router.refresh() は呼んでいない（state は入力値のまま）
```

### B. 設定画面リロード時の流れ（DB → 画面表示）

```
ブラウザリロード
  ↓
app/settings/account/page.tsx（Server Component）
  ├─ supabase.auth.getUser() → ユーザー認証
  └─ supabase.from("profiles")
       .select("username, is_admin, use_username_as_display_name")  ← 3カラム一括取得
       .eq("id", user.id).single()
     ※ error を受け取っていない → 失敗時 profile = null
  ↓
initialData を組み立て
  ├─ username: (profile?.username ?? "").trim()
  ├─ useUsernameAsDisplayName: profile?.use_username_as_display_name !== false
  └─ isAdmin: profile?.is_admin === true || 環境変数メール判定
  ↓
AccountSettingsClient（Client Component）に渡す
  └─ useState(initialData.username) で入力欄を初期化
```

### C. AI一括生成の流れ（DB → AIプロンプト）

```
ダッシュボード「AI判定を実行」ボタン
  ↓
POST /api/ai/batch
  ↓
app/api/ai/batch/route.ts
  ├─ supabase.from("profiles")
  │    .select("username, use_username_as_display_name")
  │    .eq("id", user.id).single()
  ├─ useAsDisplayName = profile?.use_username_as_display_name !== false
  └─ nickname = useAsDisplayName ? (profile?.username ?? "").trim() : ""
  ↓
nickname をプロンプトに渡す
  ├─ createStoryPrompt(..., nickname, worldConfig)     ← プロンプト本文に含む
  ├─ getStorySystemMessage(worldConfig, nickname)      ← システムメッセージにも含む ✅
  └─ createAdvicePrompt(..., nickname)                 ← プロンプト本文に含む
  ↓
AIが nickname を使ってあらすじ・アドバイスを生成
```

### D. 個別あらすじ生成の流れ（バグあり）

```
POST /api/ai/story
  ↓
app/api/ai/story/route.ts
  ├─ nickname 取得（batch と同じロジック） ✅
  ├─ createStoryPrompt(..., nickname, worldConfig)     ← プロンプト本文に含む ✅
  └─ getStorySystemMessage(worldConfig)                ← nickname 未渡し ❌
  ↓
AIがシステムメッセージで nickname 指示を受け取れない
→ 名前を省略・短縮しやすくなる
```

## 発見されたバグと改善点

### BUG: `/api/ai/story` のシステムメッセージに nickname が渡っていない

[app/api/ai/story/route.ts](web-app/gol-web/app/api/ai/story/route.ts) の107行目:

```typescript
content: getStorySystemMessage(worldConfig),  // nickname が未渡し
```

一方、一括生成 [app/api/ai/batch/route.ts](web-app/gol-web/app/api/ai/batch/route.ts) では正しく渡している:

```typescript
content: getStorySystemMessage(worldConfig, nickname),  // 正しい
```

`getStorySystemMessage` は第2引数 `nickname` がないとニックネーム使用指示をシステムメッセージに含めない。プロンプト本文にはニックネーム指示があるが、**システムメッセージの補強が欠けている**ため、AIが名前を省略・短縮しやすくなる。

### 改善: profile 保存 API の2回更新を1回に統合

[app/api/user/profile/route.ts](web-app/gol-web/app/api/user/profile/route.ts) で `username` と `use_username_as_display_name` を別々にUPDATEしている（78-107行）。2回目がサイレントに失敗する可能性がある。

マイグレーション SQL は既にあり、カラムは存在するはずなので、1回のUPDATEにまとめ、失敗時は明確にエラーを返す方が安全。

## 追加調査: ニックネーム保存後リロードで空欄になる問題

### 原因特定

**根本原因: [app/settings/account/page.tsx](web-app/gol-web/app/settings/account/page.tsx) の Supabase クエリでエラーチェックが欠落している**

```typescript
// 現在のコード（18-22行目）— error を無視している
const { data: profile } = await supabase
  .from("profiles")
  .select("username, is_admin, use_username_as_display_name")
  .eq("id", user.id)
  .single()
```

`{ data: profile }` のみを受け取り、`error` を捨てている。クエリが何らかの理由で失敗すると `profile` が `null` になり:

- `usernameFromProfile` = `(null?.username ?? "").trim()` = **`""`（空）**
- `useUsernameAsDisplayName` = `null?.use_username_as_display_name !== false` = **`true`（チェックON）**

つまり、**ユーザーの報告と完全一致: 空の入力欄 + チェックが入った状態**

### なぜクエリが失敗するのか

SELECT で `username, is_admin, use_username_as_display_name` の3カラムをまとめて取得している。このうち `is_admin` と `use_username_as_display_name` は後から追加されたカラム:

- `is_admin`: [supabase-admin-setup.sql](web-app/docs/sql-snippet/supabase-admin-setup.sql) で ALTER TABLE
- `use_username_as_display_name`: [add-use-username-as-display-name.sql](web-app/docs/sql-snippet/add-use-username-as-display-name.sql) で ALTER TABLE

**いずれかのマイグレーションが未適用の場合、Supabase PostgREST は存在しないカラムに対して HTTP 400 エラーを返す。**  
→ `profile` は `null` → username は常に空欄

一方、PATCH ハンドラ（[profile/route.ts](web-app/gol-web/app/api/user/profile/route.ts)）は `username` を最初に単独更新し、`use_username_as_display_name` は別の UPDATE（失敗してもスキップ）にしているため、**保存は成功するが読み込みだけ失敗する**という非対称が発生する。

### 修正内容

#### 修正4: page.tsx にエラーハンドリング追加

**ファイル:** [app/settings/account/page.tsx](web-app/gol-web/app/settings/account/page.tsx)

```typescript
// 修正案: エラーチェック + フォールバック
const { data: profile, error: profileError } = await supabase
  .from("profiles")
  .select("username, is_admin, use_username_as_display_name")
  .eq("id", user.id)
  .single()

// メインクエリが失敗した場合（カラム未追加等）、最低限のカラムでフォールバック
let finalProfile = profile
if (profileError) {
  console.error("プロファイル取得エラー:", profileError.message)
  const { data: fallback } = await supabase
    .from("profiles")
    .select("username")
    .eq("id", user.id)
    .single()
  finalProfile = fallback
    ? { ...fallback, is_admin: false, use_username_as_display_name: true }
    : null
}
```

これにより:
- マイグレーション済み環境: 従来どおり動作
- マイグレーション未適用: `username` だけは正しく読めるようになる（空欄にならない）
- エラーがコンソールに出力され、原因特定が容易になる
