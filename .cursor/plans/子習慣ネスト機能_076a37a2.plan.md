# 子習慣（ネスト）機能 実装計画

## 要件の整理

- 習慣に「親」「子」の関係を導入する（1階層のみ、親 → 子）。
- **完了条件**: 親のチェック **または** 子のいずれか1つのチェックで、その親習慣は「完了」とみなす。
- **表示**: 親の下に子をインデント＋チェックボックスで表示（日誌・設定の両方）。
- **報酬**: 親習慣として完了した場合、親の points/exp を **1回だけ** 加算（親をチェックしても子をチェックしても重複加算しない）。

---

## 1. データベース

**テーブル `habits` にカラム追加**

- `parent_habit_id` … `UUID NULL`、FK to `habits(id)`、ON DELETE SET NULL 推奨。
- 既存の RLS は `user_id` ベースのため、親子とも同じユーザーであればそのままでよい。
- 取得クエリは変更不要（全習慣を取得し、フロントで親子をグループ化する想定）。

**マイグレーション**

- [docs/sql-snippet/](web-app/docs/sql-snippet/) に `add-parent-habit-id.sql` を追加し、`ALTER TABLE habits ADD COLUMN parent_habit_id UUID REFERENCES habits(id) ON DELETE SET NULL` とコメントで説明を記載。

---

## 2. 型・API

- **[lib/types.ts](web-app/gol-web/lib/types.ts)**  
  - `Habit` に `parent_habit_id?: string | null` を追加。
- **習慣取得 API**  
  - 既存の `GET /api/habits` および dashboard の `habits` 取得で `parent_habit_id` を select に含める（Supabase の select に `parent_habit_id` を追加）。
- **習慣作成・更新 API**  
  - `POST/PATCH` で `parent_habit_id` を受け取り、保存できるようにする（親は自ユーザーかつ同一 `habit_type` に制限するかは任意。まずは同一ユーザーのみ検証でよい）。

---

## 3. スコア・完了判定

**習慣ログの扱い**

- 親・子それぞれに `habit_logs` の行が存在しうる（親をチェックした日は親の `habit_id` で log、子をチェックした日は子の `habit_id` で log）。
- **親の「完了」**: その日の `habit_logs` で、親の `habit_id` が `is_checked` **または** いずれかの子の `habit_id` が `is_checked` なら完了。

**スコア計算（日次・確定時）**

- **[lib/score-calculator.ts](web-app/gol-web/lib/score-calculator.ts)** で、習慣の points/exp を加算するときに「親習慣」を考慮する。
  - 親習慣（`parent_habit_id` が null で、かつ子がいる習慣）については、その日「親が完了」なら **親の** points/exp を 1 回だけ加算。
  - 子習慣は **スコア加算対象にしない**（親の完了で親の分だけ加算する）。  
  - 親習慣で子がおらず単体の習慣は、従来どおりその習慣の log が `is_checked` なら加算。
- **Complete ボーナス・exclude_from_complete**  
  - 日次「全習慣完了」判定で、親習慣は「親 or 子のいずれかで完了」なら完了とみなす。既存の `exclude_from_complete` は親・子それぞれに持たせたまま、親の完了判定だけ上記ルールに合わせる。

実装イメージ:  

- 習慣一覧と habit_logs を結合したうえで、「親習慣 ID → その日完了か」を「親の log が true または子の log のいずれかが true」で計算。
- 加算時は「親習慣 ID 単位で1回だけ」加算（親の points/exp を使用）。子習慣 ID は加算に使わない。

## 4. ダッシュボード（日誌）の習慣リスト

**[app/dashboard/habit-list.tsx](web-app/gol-web/app/dashboard/habit-list.tsx)**

- `habitsWithLogs` はこれまでどおり習慣＋その日の log を結合した配列。ここに `parent_habit_id` が含まれる想定。
- **表示用のツリー構築**:  
  - `habit_type` ごとに、`parent_habit_id == null` の習慣を「親」として `display_order` でソート。  
  - 各親の直下に、`parent_habit_id === 親.id` の子を `display_order` でソートして並べる。  
  - 同じ `goodHabits` / `badHabits` のグループ内で、フラットリストではなく「親 → 子」のツリーでレンダリングする。
- **見た目**:  
  - 親: 既存と同様の1行（チェックボックス・名前・ポイント・EXP 等）。  
  - 子: 同じ行レイアウトで、左にインデント（例: `pl-6` や `margin-left`）を付け、三角マーク等は不要（サブタスクと同様のインデントで十分）。
- **親のチェック状態の算出**:  
  - 表示上「親が完了」= 親の `habit_logs.is_checked === true` または、その子のいずれかの `habit_logs.is_checked === true`。  
  - 親のチェックボックスは、この「完了」状態と同期する（クリック時は親の `habit_id` で toggle。子のクリックは子の `habit_id` で toggle）。
- **ポイント・EXP の表示**:  
  - 親の行: 親の points/exp を表示（従来どおり）。  
  - 子の行: 子の points はスコア加算に使わないため、表示は「親と同じ報酬の一部」であることが分かるようにする（例: 親と同じ +5G 等を小さく表示するか、または「親と合わせて +5G」など）。仕様が固まっていなければ、まずは子の行には親と同じ points/exp を括弧付きで表示する程度でよい。

## 5. 設定画面（習慣の編集・並び順）

**[app/settings/habits/page.tsx](web-app/gol-web/app/settings/habits/page.tsx)**

- 習慣一覧で「親」「子」が分かるように表示（子はインデント）。
- 新規作成・編集モーダルで「親習慣」を選択できるようにする（任意: ドロップダウンで `parent_habit_id == null` の習慣のみリスト、選択時はその習慣の「子」として保存）。
- 親習慣を削除する場合、子の `parent_habit_id` は DB で SET NULL にすれば、子は通常の習慣として残る（ON DELETE SET NULL 想定）。
- 並び順: 親の `display_order` で親の並び、同じ親に属する子は子の `display_order` で並びを制御。既存の並び替え UI を、親グループ・子グループで扱えるように拡張する（まずは子の並びは「親の直下で手動並び替え」ができる程度でよい）。

## 6. 実装順序の提案

1. **DB マイグレーション** … `parent_habit_id` 追加。
2. **型・API** … `Habit` 型と GET/POST/PATCH で `parent_habit_id` を扱う。
3. **スコア計算** … `score-calculator.ts` で親習慣の「1回だけ加算」と完了判定を実装。
4. **ダッシュボード表示** … 習慣リストのツリー化・親の完了表示・子のインデント表示。
5. **設定画面** … 親習慣選択・一覧のインデント表示・並び順。

---

## 7. 注意点・今後の拡張

- 子習慣の `points`/`exp_*` は、現状「表示・AI提案用」とし、実際の加算は親の値のみ使用する。子ごとに違う報酬にしたい場合は仕様拡張が必要。
- 深さは1階層のみとし、子の子は作らない（`parent_habit_id` が null でない習慣は子としてのみ扱う）。

以上を前提に、子習慣ネスト機能の実装を進められます。
