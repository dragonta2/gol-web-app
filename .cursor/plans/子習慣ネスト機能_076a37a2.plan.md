# 子習慣（ネスト）機能 実装計画

## 要件の整理

- 習慣に「親」「子」の関係を導入する（1階層のみ、親 → 子）。
- **親習慣**: 見出しとしてのみ表示する。**チェックボックスはつけない**（ただの見出し状の見た目）。
- **子習慣**: 親の下にインデント＋チェックボックスで表示。**子にしかチェックはつかない**。
- **モーダル**: 「親習慣（子習慣を設定する）」スイッチを入れると、ToDoリストのような**サブタスク入力欄**が出現。そこで各子習慣ごとに**名前・ゴルド・EXP**を設定できる。
- **報酬**: 各子習慣ごとにゴルド・EXPが設定でき、**チェックした子の報酬**を加算する（親の報酬を1回だけ加算する仕様ではない）。親はチェックしないためスコア加算対象にならない。

---

## 1. データベース

**テーブル `habits` にカラム追加**

- `parent_habit_id` … `UUID NULL`、FK to `habits(id)`、ON DELETE SET NULL 推奨。
- 既存の RLS は `user_id` ベースのため、親子とも同じユーザーであればそのままでよい。
- 取得クエリは変更不要（全習慣を取得し、フロントで親子をグループ化する想定）。

**マイグレーション**

- `docs/sql-snippet/add-parent-habit-id.sql` に `ALTER TABLE habits ADD COLUMN parent_habit_id UUID REFERENCES habits(id) ON DELETE SET NULL` とコメントで説明を記載。

---

## 2. 型・API

- **lib/types.ts** … `Habit` に `parent_habit_id?: string | null` を追加。
- **習慣取得** … ダッシュボードの `habits` 取得で `parent_habit_id` を含める（`select("*")` で取得している場合はマイグレーション後そのまま含まれる）。
- **習慣作成・更新 API** … `POST`/`PUT` で `parent_habit_id` を受け取り、保存する（同一ユーザーの習慣のみ親として指定可能）。

---

## 3. スコア・完了判定

**習慣ログの扱い**

- 親にはチェックをつけないため、親の `habit_id` では `habit_logs` に記録されない。
- 子をチェックした日は、その子の `habit_id` で `habit_logs` に記録される。

**スコア計算（日次・確定時）**

- **lib/score-calculator.ts** で、**各習慣のチェックごとにその習慣の points/exp を加算**する。
  - チェックされた習慣（子または単体の習慣）のゴルド・EXPを加算。
  - 親習慣（子がいるもの）はチェックしないためログに乗らず、加算対象にならない。
- **Complete ボーナス** … ボーナス習慣が親（子あり）の場合は、子のいずれかがチェックされていれば「完了」とみなす（`isParentCompleted`）。単体のボーナス習慣は従来どおりその習慣のチェックで完了。

---

## 4. ダッシュボード（日誌）の習慣リスト

**app/dashboard/habit-list.tsx**

- **表示用のツリー構築**: `habit_type` ごとに、`parent_habit_id == null` の習慣を「親」として `display_order` でソート。各親の直下に、`parent_habit_id === 親.id` の子を `display_order` でソートして並べる。
- **見た目**  
  - **親（子がいる場合）**: チェックボックスなし。見出し状の1行（習慣名＋右端に「見出し」表示のみ）。フォントサイズは子習慣と同じ（`text-base`）。開始位置はチェックボックスがある行と同じ左端に揃える（余白なし）。  
  - **親（子がいない場合）**: 従来どおりチェックボックス・名前・ポイント・EXP 等。  
  - **子**: 左にインデント（`pl-6`）、チェックボックス・名前・**その子の** points/exp を表示。チェック時にその子の報酬が加算される。
- 良習慣・悪習慣・ボーナスいずれも同じルール。

---

## 5. モーダル（習慣追加・編集）

**app/dashboard/habit-list.tsx の習慣追加・編集モーダル**

- **「親習慣（子習慣を設定する）」スイッチ**: ON にすると、親は見出しのみ・子だけチェック可能なグループとして作成する。
- **子習慣入力**: ToDoのサブタスクのような入力欄を表示。
  - 各行で「子習慣名」「ゴルド（G）」「身体EXP」「頭脳EXP」「精神EXP」を設定。
  - 「+ 子習慣を追加」で行追加、「削除」で行削除。
- **保存時**:  
  - 新規で「親習慣（子習慣を設定する）」の場合 … 親習慣を1件作成（points/exp は 0）、続けて各子習慣を `parent_habit_id` 付きで作成。  
  - 編集で親（子あり）の場合 … 親の名前等を更新し、子は追加・更新・削除を同期。
- 子習慣ありのときは、単体用のポイント・EXP入力欄は非表示（親にはつけない）。

---

## 6. 設定画面（習慣の編集・並び順）

**app/settings/habits/page.tsx**

- 習慣一覧で「親」「子」が分かるように表示（子はインデント `ml-6`）。
- 親子の設定（親習慣の作成・子の追加・編集）は**ダッシュボードのモーダル**で「親習慣（子習慣を設定する）」スイッチからのみ行う。設定画面には親習慣選択のドロップダウンは設けない（既存の `parent_habit_id` は編集時そのまま送るのみ）。
- 親習慣を削除する場合、子の `parent_habit_id` は DB で SET NULL（ON DELETE SET NULL）。子は通常の習慣として残る。

---

## 7. 実装順序（参考）

1. DB マイグレーション … `parent_habit_id` 追加。
2. 型・API … `Habit` 型と GET/POST/PUT で `parent_habit_id` を扱う。
3. スコア計算 … 各習慣のチェックごとにその習慣の points/exp を加算（親はチェックしないため加算対象外）。
4. ダッシュボード表示 … 親（子あり）は見出しのみ、子はインデント＋チェック＋各子の報酬表示。
5. モーダル … 「親習慣（子習慣を設定する）」スイッチ＋子習慣のサブタスク風入力（名前・ゴルド・EXP）。
6. 設定画面 … 一覧のインデント表示（親習慣選択UIはなし）。

---

## 8. 注意点・今後の拡張

- 各子習慣は独自の `points`/`exp_*` を持ち、チェック時にその子の報酬を加算する。
- 深さは1階層のみ。子の子は作らない（`parent_habit_id` が null でない習慣は子としてのみ扱う）。

以上を前提に、子習慣ネスト機能の実装を進められます。
