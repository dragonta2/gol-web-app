# 確定ボタンでスコア反映を一括化する

## 現状（即時反映）

- 習慣チェック → 即座に profiles 加減算（`POST /api/habit-logs`）
- ToDo完了 → 即座に profiles 加減算（`handleTaskCompletion` in `kanban-board.tsx` / `todo-summary-tab.tsx`）
- AI一括生成 → 即座に profiles 加算（`POST /api/ai/batch` のステップ6）
- 確定ボタン → `is_confirmed = true` にするだけ（編集ロック用）

## 変更後（確定で反映）

- 習慣/ToDo/AI → 各ログテーブルに記録するが **profiles は触らない**
- 確定ボタン → 1日分のデルタを集計し **profiles にまとめて反映**
- 確定取り消し → 適用済みデルタを profiles から正確に差し引く
- 当日も確定したら**編集ロック**（今の「当日は確定後も編集可能」を変更）
- ダッシュボードに「未確定: +XG」のような仮スコア表示を追加

## 変更の影響範囲（概算: 10+ファイル、中〜大規模）

---

## Phase 1: DB変更 — 適用済みデルタの記録カラム追加

確定取り消し時に正確に巻き戻すため、確定時に適用したデルタを daily_logs に記録する。

- 新規SQL: `docs/sql-snippet/add-confirmed-deltas-to-daily-logs.sql`
- 追加カラム:
  - `confirmed_points_delta` (INTEGER DEFAULT 0)
  - `confirmed_exp_body_delta` (INTEGER DEFAULT 0)
  - `confirmed_exp_mind_delta` (INTEGER DEFAULT 0)
  - `confirmed_exp_spirit_delta` (INTEGER DEFAULT 0)
- `lib/types.ts` の `DailyLog` 型にも追加

## Phase 3: 確定/取り消しAPIの新規実装

**3-1. デルタ集計ロジック** — 新規 `lib/score-calculator.ts`

- `calculateDayDeltas(dailyLogId)`: 1日分の全デルタを集計して返す共通関数
  - habit_logs: その日の全習慣ログを取得し、チェック済み分のポイント/EXPを合算（良習慣=加算、悪習慣=減算、週末除外考慮）
  - todo_logs: その日の全ToDoログを取得し、報酬分を合算
  - daily_logs.ai_*: AI判定のポイント/EXP
  - 権利: daily_logs の right_*_count × 各権利の points を合算（消費=減算）
- 戻り値: `{ points_delta, exp_body_delta, exp_mind_delta, exp_spirit_delta }`

**3-2. 確定API** — 新規 `app/api/daily-logs/confirm/route.ts`

- `POST /api/daily-logs/confirm`
- 処理:
  1. 認証・所有権チェック
  2. `calculateDayDeltas` でデルタ算出
  3. daily_logs を UPDATE: `is_confirmed = true` + `confirmed_*_delta` にデルタを保存
  4. profiles を UPDATE: 各スコアにデルタを加算
  5. トランザクション的に一括実行（Supabase RPC または連続 UPDATE）

**3-3. 確定取り消しAPI** — 新規 `app/api/daily-logs/unconfirm/route.ts`

- `POST /api/daily-logs/unconfirm`
- 処理:
  1. 認証・所有権チェック
  2. daily_logs から `confirmed_*_delta` を読み取り
  3. profiles を UPDATE: 各スコアからデルタを減算（0未満にならないよう制限）
  4. daily_logs を UPDATE: `is_confirmed = false` + `confirmed_*_delta` をリセット

## Phase 5: 未確定スコアの表示

**5-1. 未確定デルタの取得**

- [gol-web/app/dashboard/page.tsx](web-app/gol-web/app/dashboard/page.tsx):
  - 当日（選択日）の daily_log が未確定なら、habit_logs / todo_logs / ai_* / 権利から仮デルタを計算してクライアントに渡す
  - または、クライアント側で計算（既にデータは取得済みなので）

**5-2. ダッシュボード表示**

- ヘッダーのゴルド/EXP: 確定済み合計（profiles の値）を表示
- その横または下に「未確定: +XG / 身体+Y / ...」を別色・別スタイルで表示
- 確定ボタンを押すと未確定分が確定済みに移る

## リスクと注意点

- **既存データの整合性**: この変更前にすでに即時反映で profiles に加算されたデータがある。移行時にリセット等は不要（過去分はそのまま。変更後の新しい日から新仕様が適用される想定）
- **権利ポイントの仕様確認**: 権利（利用ゴルド）は現在 daily_logs に count を保存しているだけで profiles から減算する処理がない。この機会に「確定時に権利消費分を profiles.points から減算する」仕様を入れるかどうかを決める必要がある
- **パフォーマンス**: 確定時に habit_logs + todo_logs を集計するクエリが走るが、1日分なのでデータ量は少なく問題なし
