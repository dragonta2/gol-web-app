# 表示名がデフォルトになる原因調査

あらすじ・アドバイスに「設定した名前」ではなくデフォルト名（辰彦・勇者など）が出る場合の切り分け用メモ。

## 表示名が決まる流れ

1. **設定画面（アカウント）**  
   - 「表示名」入力 → 保存で `POST /api/user/profile` に `username` と `use_username_as_display_name` を送る。  
   - DB の `profiles.username` と `profiles.use_username_as_display_name` が更新される。

2. **AI一括生成（バッチAPI）**  
   - `GET /api/ai/batch` 内で `profiles` を取得。  
   - `use_username_as_display_name !== false` なら `nickname = profiles.username`、そうでなければ `nickname = ''`。  
   - この `nickname` をプロンプト（あらすじ・アドバイス）に渡している。

3. **プロンプト側**  
   - `nickname` が空 → 世界観のデフォルト名（辰彦 / 勇者）だけを使う指示になる。  
   - `nickname` が入っている → 「このニックネームを省略せず使う」指示になる。

## 原因の切り分け

### 1. API が「空」の表示名を使っている

**確認方法**

- 開発時: 一括生成成功トーストの説明に「表示名: （未設定）」や「表示名: 〇〇」が出る。  
  - 「（未設定）」→ サーバーで `nickname` が空。下記 2 か 3 の可能性。
- 本番: ブラウザの DevTools → Network → `batch` のレスポンスの `_debug_nickname_used` を確認（開発時のみレスポンスに含まれる想定）。  
- サーバーログ: 開発時は `[AI batch] display name check` で `username_from_db` と `nickname_used` が出力される。

**考えられる原因**

| 原因 | 確認方法・対処 |
|------|----------------|
| **A. `profiles.username` が空** | Supabase の `profiles` で該当ユーザーの `username` を確認。設定画面で表示名を入力して「保存」しているか確認。 |
| **B. `use_username_as_display_name` が false** | `profiles.use_username_as_display_name` を確認。「この名前をGOL世界の表示名として利用する」にチェックを入れて保存しているか確認。 |
| **C. カラムがない** | `use_username_as_display_name` が無いと、フラグは `undefined` で `!== false` は true になるため、通常は B ほどは起きにくい。 |

### 2. API は正しい表示名を使っているが、AI が短くしている

**確認方法**

- トーストや `_debug_nickname_used` で「表示名: 篤dragon5555555」のようにフルネームが出ているのに、あらすじでは「篤」だけになる場合。

**対処**

- プロンプト・システムメッセージではすでに「省略・短縮・置き換えせずそのまま使う」と入れている。  
- それでも短くなる場合は、プロンプトの文言をさらに強くするか、表記例を複数入れるなどの調整が必要。

### 3. 設定保存と参照のタイミング

- バッチAPI は**そのリクエスト時点の** `profiles` を読む。  
- 設定画面で保存した直後に「AI判定を実行」していれば、通常は最新の `username` が使われる。  
- 別デバイスや別タブで変更した場合は、そのユーザーで再度一括生成すれば反映される。

## まとめ

1. まず「表示名: 〇〇」で、API が**何を**渡しているか確認する。  
2. 「（未設定）」や空 → DB の `profiles.username` と「GOL世界の表示名として利用する」の保存を確認。  
3. 正しい名前が渡っているのに短い名前になる → モデル側の解釈なので、プロンプトの強化を検討する。
