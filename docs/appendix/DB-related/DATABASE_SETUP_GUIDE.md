# データベーステーブル作成ガイド

## セキュリティについて

### ✅ データ漏洩・情報漏洩の対策

このシステムは以下のセキュリティ対策が実装されています：

1. **Row Level Security (RLS)**: ユーザーは自分のデータのみアクセス可能
2. **認証チェック**: ログインしていないユーザーはデータにアクセス不可
3. **RLSポリシー**: すべてのテーブルでRLSが有効化されている
4. **CASCADE削除**: ユーザー削除時に関連データも自動削除

### 🔒 セキュリティの仕組み

```
┌─────────────────────────────────────────┐
│ ユーザーA (ログイン中)                   │
│ auth.uid() = "user-a-uuid"              │
└─────────────────────────────────────────┘
                    │
                    │ SELECTクエリ
                    ▼
┌─────────────────────────────────────────┐
│ RLSポリシー: auth.uid() = user_id       │
│ → user_id = "user-a-uuid" のデータのみ  │
└─────────────────────────────────────────┘
                    │
                    ▼
┌─────────────────────────────────────────┐
│ ai_usage_logs テーブル                   │
│ - user_id = "user-a-uuid" の行のみ返す  │
│ - 他のユーザーのデータは見えない         │
└─────────────────────────────────────────┘
```

### 🛡️ データ漏洩が発生しない理由

| 対策 | 説明 |
|------|------|
| **RLS有効化** | `ALTER TABLE ai_usage_logs ENABLE ROW LEVEL SECURITY;` により、テーブルレベルでアクセス制御 |
| **SELECTポリシー** | `auth.uid() = user_id` により、自分のユーザーIDと一致するデータのみ取得可能 |
| **INSERTポリシー** | `WITH CHECK (auth.uid() = user_id)` により、自分のデータのみ挿入可能 |
| **認証必須** | ログインしていないユーザー（`auth.uid()`が`NULL`）はすべてのデータにアクセス不可 |
| **外部キー制約** | `REFERENCES profiles(id) ON DELETE CASCADE` により、ユーザー削除時に関連データも削除 |

### ⚠️ 注意事項

1. **Supabaseの設定確認**: SupabaseプロジェクトでRLSが有効になっていることを確認
2. **APIキーの管理**: `NEXT_PUBLIC_SUPABASE_ANON_KEY`は公開鍵ですが、RLSにより保護される
3. **データベースアクセス**: Supabaseのダッシュボードから直接アクセスする場合は、管理者権限で操作してください

## データベーステーブル作成手順

### ステップ1: Supabaseダッシュボードにアクセス

1. **Supabaseダッシュボードを開く**
   - https://app.supabase.com にアクセス
   - プロジェクトを選択

2. **SQL Editorを開く**
   - 左メニューから「**SQL Editor**」をクリック
   - 左サイドバーの「SQL Editor」セクション内で、「Q Search queries...」という検索バーの右側にある **「+」ボタン（プラスアイコン）** をクリック
   - メニューが表示されたら、**「Create a new snippet」** を選択してください
     - ⚠️ 「Create a new folder」ではなく、「Create a new snippet」を選びます
   - これで新しいクエリタブ（スニペット）が開きます

### ステップ2: SQLファイルの内容をコピー

1. **SQLファイルを開く**
   ```
   /Users/ta2/Develop/dta2/gol/web-app/docs/supabase-ai-usage-setup.sql
   ```

2. **ファイルの内容をすべてコピー**
   - コマンド + A で全選択
   - コマンド + C でコピー

### ステップ3: Supabase SQL Editorで実行

1. **SQL Editorに貼り付け**
   - SupabaseのSQL Editorにコピーした内容を貼り付け（コマンド + V）

2. **実行ボタンをクリック**
   - 右上の「**Run**」ボタンをクリック
   - または `Ctrl + Enter`（Windows/Linux）または `Cmd + Enter`（Mac）

3. **実行結果を確認**
   - 成功の場合: 「Success. No rows returned」と表示される
   - エラーの場合: エラーメッセージが表示される

### ステップ4: テーブル作成の確認

1. **Table Editorで確認**
   - 左メニューから「**Table Editor**」をクリック
   - 「**ai_usage_logs**」テーブルが表示されることを確認

2. **RLSポリシーの確認**
   - 「**ai_usage_logs**」テーブル名をクリック（テーブルを選択）
   - テーブルの詳細画面が開いたら、上部のコントロールバーを確認します
   - 「**Insert**」ボタンの右側に「**RLS policies**」というボタンがあります ← **このボタンをクリック**
   - 「RLS policies」ボタンには「2」というバッジが表示されているはずです（2つのポリシーが設定されていることを示します）
   - 「**RLS policies**」ボタンをクリック
   - 以下のポリシーが作成されていることを確認：
     - `Users can view own ai usage logs` (SELECT)
     - `Users can insert own ai usage logs` (INSERT)

### ステップ5: 動作確認

1. **アプリを再起動**（必要に応じて）
   ```bash
   npm run dev
   ```

2. **AI判定を実行**
   - ダッシュボード → 日誌タブ → AI判定を実行

3. **使用量を確認**
   - ダッシュボードにログイン
   - ダッシュボード上部のタブナビゲーションを確認：
     - 「日誌」タブ（🏠アイコン）
     - 「ToDoサマリー」タブ（📋アイコン）
     - 「**統計**」タブ（📊アイコン）← **このタブをクリック**
   - 「統計」タブを開きます
   - **重要**: 「AI使用量」セクションが表示されるには、以下の条件が必要です：
     1. ✅ データベーステーブル（`ai_usage_logs`）が作成されている（完了済み）
     2. ✅ RLSポリシーが設定されている（完了済み）
     3. ⚠️ **実際にAI判定を実行している**（使用量データが存在する）
   - **現在の状態**: 「AI使用量」セクションが表示されていない場合、以下のいずれかが原因です：
     - **原因1**: AI判定をまだ実行していない（最も可能性が高い）
       - **対処法**: 「日誌」タブに戻って、日誌を入力し、「AI判定を実行」ボタンをクリックしてください
       - AI判定を実行すると、使用量が記録されます
       - その後、「統計」タブに戻ると「AI使用量」セクションが表示されます
     - **原因2**: データベースのRPC関数が作成されていない
       - **確認方法**: ブラウザの開発者ツール（F12）→ Consoleタブでエラーを確認
       - **対処法**: `supabase-ai-usage-setup.sql`の「3. 使用量集計関数」セクションを実行してください
     - **原因3**: APIエラーが発生している
       - **確認方法**: ブラウザの開発者ツール（F12）→ Networkタブで`/api/ai/usage`のレスポンスを確認
   - 表示内容（AI判定実行後）：
     - 今日のコスト
     - 今月のコスト
     - 今日の判定回数
     - 今月の判定回数
     - 日別使用量グラフ（過去30日）

   SELECT tablename, rowsecurity

   SELECT policyname, cmd, qual, with_check

## 補足情報

### データが保存される内容

- **トークン使用量**: 入力/出力/合計トークン数
- **コスト**: 入力/出力/合計コスト（USD）
- **メタデータ**: モデル名、ステータス、エラーメッセージ
- **タイムスタンプ**: リクエスト日時

### 保存されない情報

- **APIキー**: APIキーは保存されません（環境変数のみ）
- **日誌本文**: 日誌の内容は`ai_usage_logs`には保存されません（`daily_logs`テーブルに保存）
- **個人情報**: ユーザー名やメールアドレスなどの個人情報は`profiles`テーブルに保存

### プライバシーについて

- すべてのデータはRLSにより保護されています
- ユーザーは自分のデータのみアクセス可能です
- 他のユーザーのデータを見ることはできません
- Supabaseの管理者であっても、RLSにより他のユーザーのデータを見ることはできません（明示的にポリシーを無効化しない限り）
