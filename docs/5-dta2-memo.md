### 260319-木 --------------

#### 260319-木｜`type="date"` セグメントフォーカスのCSSスタイリング

**記載** ClaudeCode

- `type="date"` の入力欄は YYYY / MM / DD の各セグメントに分かれており、アクティブなセグメントは `::-webkit-datetime-edit-year-field:focus` などの WebKit 疑似要素でスタイリングできる

- `background`, `color`, `-webkit-text-fill-color` を `!important` で指定することでフォーカスセグメントの背景色・文字色を変更できる

- ただし WebKit / Chrome はブラウザ内部でデフォルトの青いハイライトを適用しており、CSS で完全には上書きできない場合がある（OS・ブラウザバージョンによって挙動が異なる）

- `@layer base` 内に `input:focus::-webkit-datetime-edit-*` で `background: transparent !important` を書くと、セグメント個別のフォーカス指定と競合して意図しない上書きが起きる → レイヤー外に書くか、競合ルールを削除する

## エンジニアの新しい役割（AI時代）

### 従来の役割: コードを書く人
```

要件 → 設計 → 実装 → テスト → リリース
     ↑ すべて人間がやっていた

```

### 新しい役割: コードを指揮する人

```

要件 → 設計 → AI に指示 → レビュー・調整 → テスト → リリース
              ↑              ↑
           AIが書く      人間が判断

```

**エンジニアの価値:**

- **判断力**: 何を作るか、どう作るか

- **設計力**: 全体の構造、拡張性、保守性

- **UX視点**: ユーザーにとって使いやすいか

- **品質管理**: AIが書いたコードのレビュー、改善

- **問題解決**: 新しい課題への創造的アプローチ

## フロントエンドエンジニアとしての学習戦略（251121）

### コードを読むだけでは書けるようにならない

**問題点:**
- 処理をひとつひとつ全て読んでいたら日が暮れる
- 読んだだけでは理解できていない
- 自分では書けなかったろうなと思う

**解決策: 段階的に理解を深める**

### 1. 全体像を先に把握する

**現在のアプローチ:**
- コードを読んで全体像を把握
- 各コンポーネントの役割を理解

**メリット:**
- 全体の流れが見える
- どこに何があるか分かる

**デメリット:**
- 細部まで読むと時間がかかる
- 読んだだけでは書けるようにならない

### 2. 実践しながら学ぶ（推奨）

**アプローチ:**
1. 全体像を把握（今の段階）
2. 小さな変更から始める
3. エラーを見て学ぶ
4. パターンを理解する

**具体例:**

#### ステップ1: 簡単な変更から
```
例: ボタンの色を変える
- 現在: bg-cyan-600
- 変更: bg-blue-600
- 結果: 色が変わる → 「Tailwindの色指定が分かった！」
```

#### ステップ2: 少し複雑な変更
```
例: ボタンにアイコンを追加
- 現在: 「ログイン」テキストのみ
- 変更: 「🔐 ログイン」にアイコン追加
- 結果: アイコンが表示される → 「JSXで絵文字が使える！」
```

#### ステップ3: ロジックの変更
```
例: エラーメッセージの表示を変更
- 現在: エラー時のみ表示
- 変更: 常に表示エリアを確保（高さ固定）
- 結果: レイアウトが安定 → 「条件付きレンダリングが分かった！」
```

### 3. パターンを理解する（重要）

コードを全部読むのではなく、パターンを覚える。

**よく使うパターン:**

#### パターン1: フォーム入力
```typescript
// このパターンを覚える
const [value, setValue] = useState('');
<input 
  value={value}
  onChange={(e) => setValue(e.target.value)}
/>
```

#### パターン2: データ取得（Server Component）
```typescript
// このパターンを覚える
const supabase = await createClient();
const { data } = await supabase
  .from('table_name')
  .select('*')
  .eq('user_id', user.id);
```

#### パターン3: データ更新（Client Component）
```typescript
// このパターンを覚える
const supabase = createClient();
await supabase
  .from('table_name')
  .update({ field: newValue })
  .eq('id', id);
```

### 4. 段階的な学習プラン

**Phase A: 基礎理解（1-2週間）**
- 全体像を把握（今の段階）
- 主要なパターンを覚える
- 小さな変更を試す

**Phase B: 実践（2-4週間）**
- 既存コードをコピーして改造
- エラーを見て学ぶ
- 同じパターンを繰り返し使う

**Phase C: 応用（1-2ヶ月）**
- 新しい機能を追加
- パターンを組み合わせる
- 自分で設計できるようになる

### 5. 具体的な学習方法

#### 方法1: コピー&改造
```
1. 既存のコードをコピー
2. 少しだけ変更してみる
3. 動かして確認
4. エラーが出たら調べる
```

**例:**
```typescript
// 既存: ログインボタン
<button onClick={handleLogin}>ログイン</button>

// 改造: アイコン追加
<button onClick={handleLogin}>🔐 ログイン</button>

// 改造: 色変更
<button onClick={handleLogin} className="bg-blue-600">🔐 ログイン</button>
```

#### 方法2: エラーから学ぶ
```
1. コードを変更
2. エラーが出る
3. エラーメッセージを読む
4. 調べて修正
5. 理解が深まる
```

#### 方法3: パターン集を作る
```
自分用のメモ:
- フォーム入力のパターン
- データ取得のパターン
- データ更新のパターン
- エラーハンドリングのパターン
```

### 6. 学習の優先順位

**今すぐ覚えるべきこと:**
1. useStateの基本パターン
2. propsの受け渡し
3. Supabaseの基本操作（SELECT、UPDATE、INSERT）

**後で覚えればいいこと:**
1. 高度なTypeScript型定義
2. 複雑な最適化
3. 全てのTailwindクラス

**覚えなくてもいいこと:**
1. 全てのコードを暗記
2. 全てのAPI仕様
3. 全てのライブラリの詳細

### 7. 実践的な学習戦略のまとめ

**1. 全体像は把握済み → 細部は必要になったら読む**

**2. パターンを覚える → 全部読むのではなく、よく使うパターンを覚える**

**3. 小さな変更から始める → エラーを見て学ぶ**

**4. 実践を優先 → 読むより書く、コピー&改造から始める**

**5. エラーを恐れない → エラーは学習の機会**

**次のステップ:**
- Phase 2の残りタスク（ToDoカンバンDB連携）を実装
- 既存のパターン（habit-list.tsx、journal-form.tsx）を参考にする
- エラーが出たら調べて修正
- 実践しながら理解を深める
